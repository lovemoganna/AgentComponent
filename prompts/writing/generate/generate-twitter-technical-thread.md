# 用途

把已有技术材料炼成适合 Twitter / X 技术圈发布的中英双语 Thread，突出真实机制、工作流和独特价值，而不是生成泛化的社交媒体文案。

# Prompt

将输入材料炼成一组适合 Twitter / X 技术圈发布的中英双语 Thread。

目标不是简单总结材料，也不是把内容改写成长文章。先找出材料中最值得传播的中心判断，再围绕这个判断组织 8 至 10 条 Thread。重点说明真实发生了什么、核心机制是什么、这套做法与常见做法有什么不同，以及它为什么值得技术用户关注。

按专家撰文 Style 输出。保持技术深度，但压缩复杂表达。只保留支持中心判断的事实、机制、技术细节、工作流和判断。删除重复解释、空泛总结、宣传式表达和不能增加信息价值的修饰。

如果输入中有多份内容回答同一个问题，合并为一条完整叙事。如果不同内容承担独立职责，则保持分开，不强行合并。

必须保留输入中的真实事实、数字、名称、项目名、文件名、工具名、技术细节、流程、限制和状态。不得改写事实基础，不得补充未经确认的能力，不得把推测写成事实。信息不足时，保留不确定性，不自行补全。

如果材料描述具体工作流，必须写清真实动作，不使用抽象概括替代。例如应说明 AI 实际读取什么、扫描什么、如何判断、修改什么、如何验证、如何进入 Git，以及最终如何发布。重点突出系统真正执行的动作，而不是只写“AI 提高效率”之类的结论。

优先突出独特价值。如果材料涉及 Prompt、Skill、GitHub、Org Mode、Git、Agent 或知识库，应说明各组件分别承担什么职责，以及这些组件如何组成完整闭环。不要把核心价值简化为“AI 自动写文章”。如果真实流程包含内容收录、知识匹配、炼化、旧文增量修改、结果检查、Diff、回滚、提交和发布，应保留这些关键环节。

每条 Thread 只承担一个主要意思。先给结论或事实，再解释必要机制。使用短句、明确主语和实义动词。避免长句、抽象词、同义反复和复杂修辞。保持技术人的自然表达，不写成产品宣传、教程说明书或完整博客。

中英文必须放在同一条 Thread 内。先中文，后英文，中间不额外拆成两个语言区。英文必须完整对应中文，不得缩成摘要，也不得新增中文没有的信息。事实、主体、数字、技术名称、判断、限定条件和确定性必须保持一致。

标题使用“中文 | English”格式。标题只负责定位主题，不承担完整论证。

输出使用 8 至 10 条编号 Thread。不得使用装饰性分隔线、Emoji 或明显的 AI 排版符号。除 Thread 编号外，不增加多余标题和列表。

最终内容必须满足四个验收条件：读者能快速看懂真实工作流；读者能看出这套做法与普通 AI 内容生成的区别；技术细节足以支撑中心判断；删除任何一条核心内容后，整体论证都会明显变弱。

# 使用条件

- 适用于已有事实、经验、案例、技术工作流或系统说明，需要转换为 Twitter / X 技术 Thread 的场景。
- 适合技术用户、开发者、Emacs / Org Mode 用户、AI Agent 或工具工作流相关内容。
- 输入材料必须提供需要保留的事实基础；Prompt 不负责补齐缺失事实。
- 双语输出要求中文和英文信息对等，不适合只需要单语内容的任务。
- 默认输出 8 至 10 条 Thread；如果材料不足以支撑该长度，应优先保持事实密度，不得用空话补足。
